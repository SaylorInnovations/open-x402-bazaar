# Example: an ongoing project

Template — replace with a real project once one exists. A good project entry
covers:

- **Current state** — what's built, what's in progress, what's blocked.
- **Why** — the motivation or constraint driving it (a deadline, a request, a
  bug report), so priority decisions make sense later.
- **Next action** — the single next concrete step, not a whole roadmap.

Convert relative dates ("next week") to absolute ones when writing — this file
gets read again after time has passed, and "next week" won't mean anything by
then. Update this file in place as state changes; it should always reflect
*now*, not a history of every change (that's what dated handoffs are for).

Delete this file once a real project replaces it.
